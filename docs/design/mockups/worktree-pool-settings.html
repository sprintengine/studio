Pool

Reuse worktrees for new chats
A new chat or an agent's worktree comes from the pool instead of a fresh checkout, reset to the default branch as fetched at that moment. Its ignored files (node_modules, build output) are kept, so installs are faster.
Ready worktrees to keep
Per project. When a chat is done and its worktree comes back, any beyond this are removed, longest unused first.
3
Most worktrees per project new
Counting the ones in use. Past this a new chat still gets a worktree, but a fresh one that is removed when the chat is done, not kept for reuse.
12
Disk limit new
For all of the pool's worktrees together. Past it, the longest-unused ready ones are removed. Nothing in use or holding work is ever removed, and worktrees outside the pool don't count.
Location
Next to each project, in a folder per project.
<project>/../.sprintengine-worktrees/<project>/

The service has `keepIdle` (max 6) and a fixed `POOL_MAX_SLOTS = 32`. "Most per project" makes that cap a setting. A disk limit needs the sizes above and eviction by LRU in `evictOverLimit`. When the switch is off, the rows below it are disabled, but the list stays visible so existing slots can still be cleared.
