# Design Wizard — golden-path run checklist

Release gate for changes that touch the Design Wizard (the `guided-brief`
workspace: strategist / architect / designer specialists, the design-system
studio, and the release/attach pipeline). Layers 1–2 of the verification harness
(MC-1506) run automatically in `npm run verify:app`; this is the manual layer a
real agent run has to pass before a wizard-touching release, because a live agent
run is not drivable headless (nondeterministic output, no CLI run-driver, renderer
unobservable). Kept to ten checks so it is actually run.

Record the result — pass/fail per check, the app version, and the date — in the
release notes and in the source Backlog item
(`backlog/2026-07-07-wizard-verification-harness.md`).

## Setup

1. Build/launch the app you intend to ship (not a dev server pointed at stale
   renderer bytes — see the built-Electron stale-renderer caveat).
2. Have a real agent CLI installed and authenticated (Claude Code or Codex).
3. Fixture seed: use the committed mini-app at
   `resources/design-system/verify-fixture/mini-app/` as the "seed from an
   existing product" source. It is deliberately tiny and **not** the multicode
   repo, so the run is fast and reproducible.

## Checklist (design-system preset)

Run the Design Wizard with the **Design system** preset, seeding from the fixture
mini-app above.

1. **Session honesty.** The designer specialist appears in the Sessions popover
   with a live status that matches reality (working while it authors, idle when
   it stops). It is not shown as a second, duplicate row.
2. **Run-scoped index.** The Design Files pane lists only files the run owns —
   `design-system/**` and `.guided-brief/inspiration/**`. The fixture's own
   source files (its CSS/HTML) are read by the agent but never appear in the
   index.
3. **Honest counts.** The Activity subline counts only `design-system/**` bundle
   files ("N files in the bundle"); inspiration files are listed, never counted.
4. **Seeded inferences flagged.** Tokens the agent inferred from the fixture are
   marked `"seeded": true` in the token metadata until you confirm them in the
   interview.
5. **Not ready on a broken bundle.** While the bundle is incomplete or fails
   `scripts/lint.mjs`, the stage does **not** flip to ready — even if the agent
   printed its `DESIGN_SYSTEM_READY` marker. The marker alone never flips a stage.
6. **Ready only after lint-clean + quiet.** The stage flips to ready only once the
   manifest parses, the bundle lints clean, and the agent is idle.
7. **Release runs the real gate.** The release action re-runs the bundle lint (a
   passing preview is never a bypass), regenerates derived files, and lands an
   immutable versioned copy under the library (`~/.multicode/design-systems/`).
8. **Immutability.** Releasing the same name+version again is refused; bumping the
   version produces a sibling copy.
9. **Attach injects the prompt line.** In a second, separate workspace, attach the
   released design system. A mockup/frontend designer session there gains the
   "conform to the attached design system" line in its startup prompt; a session
   with no attached bundle does not.
10. **No stray writes.** After the run, the workspace contains the bundle and the
    wizard's own scaffold artifacts — no sample/demo content the scaffold never
    authored, and no derived files that were not regenerated by the bundle's own
    scripts.

## Refreshing the harness fixtures

Layer 2's adversarial sequences are authored inline (deterministic constructed
event streams), so they need no capture. If you want to refresh them from a real
run's stream instead, both transports are replayable:

- **Conversation transport (default).** The persisted JSONL transcript under
  `.multi-code/conversations/<workspace-id>/` is already a replayable fixture —
  copy the relevant `content_delta` / `approval_requested` / `session_closed`
  events into `conversationSessionAdapter.test.ts`.
- **PTY fallback.** There is no persisted transcript; capture the raw terminal
  bytes (the `onTerminalData` stream — ANSI, CR overwrites, and all) during a
  real run and paste the chunks into `guidedBriefPtyMarkerContract.test.ts`. Keep
  chunks small and split markers across chunk boundaries, since that is the case
  the buffer has to survive.

Refreshing the seed fixture: edit
`resources/design-system/verify-fixture/mini-app/` directly. Keep it small —
a handful of `:root` custom properties, one component, one glyph — so this
checklist stays quick to run.
