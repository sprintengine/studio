Design notes
  • Quality I'm matching: Raycast’s glyph-led dense rows with two-tier hover (grip + invocation revealed on hover), and Linear’s one-calm-row-height rhythm (34px rows, even rest between the Skills and MCP groups via space + heading, not a divider).
  • Toolbelt-first, not a storefront. Per the north star, install/browse is a Settings job. The aside leads with what you reach for; “available to install” and “browse MCP catalog” are disclosures that expand in place or hand off to Settings — they never push a 3-tab store into the 296px gutter.
  • One model behind it. Built on an extended deriveInstalledExtensions() — today it omits built-in skills, so phase 1 folds the builtin-skills:* source into the same view-model so Settings and the aside can’t drift (AC #5).
  • Drag reuses existing machinery. A new skill-drop payload feeds the same renderSkillInvocationTemplate() + plugin skillIntegration.invocation lookup + worktree/slash gating that backlog drops already use (AC #2). No parallel inject logic.
  • Status is earned. Installed/healthy rows carry no mark — the resting state. Only two marks appear: a Spinner for “installing”, and a shape-coded “!” for a failed MCP sync. No dot-soup, no pills.
  • One accent. Green carries selection (the 2px rail + soft fill), the Install CTA, the enable toggle’s on-state, and the terminal drop indicator — and nothing else. The --tool-sprintengine gold dot retires with the SE aside.
  • Copy distinguishes every state — installed vs available vs installing vs sync-failed vs empty vs degraded vs dead-session. A failed source is a notice, never a blank list.
  • Accessibility: rows are focusable; drag has a keyboard equivalent (Enter on a focused skill → “inject into active agent”); the toggle is a real role="switch"; the drop indicator pairs with an aria-live “Inject Backlog into auth-refactor?” announcement.
Quantified-restraint self-audit
✓ 1 accent (green) — selection, Install, toggle-on, drop line share it
✓ Status idioms: Spinner + “!” glyph only; toggle is a control, not status
✓ 3 font sizes (12.5 / 11 body-meta / mono 11), repeating rhythm
✓ 1 border radius family (6–8px); no 2xl/3xl on chrome
✓ ≤4 elements per row at rest (grip hidden until hover)
✓ Hairline structure only — groups separated by space + heading
✓ No card-in-card; aside is one surface on --bg-app
✓ Motion: spinner (“alive”) only; no ambient decoration
