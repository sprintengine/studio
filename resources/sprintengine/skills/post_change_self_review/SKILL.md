# Post-Change Self-Review

After changing code, tests, configuration, documentation, prompts, plans, or review artifacts, inspect your own diff in context before handoff.

Re-read the request and acceptance criteria, then check for bugs, regressions, missed edge cases, hallucinated APIs or files, security issues, performance issues, code quality problems, operational risks, placeholder behavior, over-engineering, weak evidence, and acceptance criteria that could pass on mocks, fakes, fixtures, hardcoded samples, or disconnected UI state.

Fix every material issue found, then repeat the review on the updated work. Run the most relevant verification available and disclose any remaining uncertainty.
